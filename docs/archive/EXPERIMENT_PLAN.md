# Experiment plan — Member A visual proxy CNN

All experiments share seed **42**, the same 70/15/15 split (same `image_id`s
regenerated by `make_stratified_split`), the same `v2_log_shrunk` proxy labels
unless the row says otherwise, batch size 64, ImageNet pretrained weights and
validation **macro F1 over all 3 labels** for model selection. Each experiment
writes to its own `--output_dir`. The untouched test split is evaluated **once**,
for the final winner only. Historical checkpoints are never overwritten.

> Result columns are `PENDING` until a real Kaggle run fills them. never copy a
> number from another experiment or from the historical logs.

## 3. Mandatory discipline

1. Seed 42 everywhere; never change `--max_images` for a real run.
2. Test split untouched until selection is locked. No test-time threshold or
   hyperparameter tuning, ever.
3. Select on validation macro F1 **with per-class F1 and support** reported.
4. Same split and labels for all comparable rows (see `e9` exception).
5. Separate output dirs; no writes to `/kaggle/working/output` root or the
   historical `baseline` / `improved_mobilenet` folders.
6. Config/checkpoint metadata, duration and peak GPU memory captured in
   `training_summary.json`, `experiment_run.json` and the checkpoint itself.
7. Failed experiments are recorded in `docs/EXPERIMENT_RESULTS.md` with the
   failure reason. No fabricated or estimated numbers.
8. Final test evaluation runs **once** for the selected winner:
   `!python src/evaluate.py --output_dir /kaggle/working/output/experiments/<winner>`
   (add `--eval` to the runner only when you have made that decision).
9. If no new model convincingly beats the incumbent on validation macro F1,
   keep `/kaggle/working/output/improved_mobilenet/models/best_model.pth`.

## 4. Frozen-feature probe (diagnostic, separate protocol)

```python
!python src/probe.py --output_dir /kaggle/working/output/experiments/e0_reference \
    --feature_source pretrained
```

Train→val only; never test. Results go to `results/probe_results.json`. An
ImageNet-feature probe near the CNN's validation F1 suggests a feature/label
ceiling; much higher suggests a training-recipe bottleneck. Existing evidence:
probe 0.4561 vs improved CNN validation 0.4521 → ceiling is the more likely
constraint. Probe numbers must never be reported as CNN results.

## 6. Deferred experiments (not implemented, no results claimed)

- **Regression head / ordinal logits:** would change the 3-class checkpoint and
  `condition_score` contract used by Member B. Needs a separate API version.
- **Validation-tuned decision thresholds:** legitimate as a *reporting* layer,
  but must never touch the test split or redefine `condition_score`. Left out of
  this round to keep the selection metric singular and auditable.
- **Group-aware splits** (street/city grouped K-fold): only worth the extra
  complexity if §5 finds material leakage.
